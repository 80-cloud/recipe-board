## 1. プロジェクト概要

### 1-1. 背景・課題

#### 背景
- 個人で料理をする際、自分で考案・改良したレシピを**紙のメモやスマホメモで散在管理**しており、必要な時に見返しにくい
- 既存のレシピサービス（クックパッド等）は**他人のレシピ閲覧が中心**で、個人の備忘録には過剰

#### 現在の課題
- レシピが複数の場所に分散して見つからない
- 材料・手順を整理された形で保存・編集できない
- 検索・絞り込みができない

#### 解決策
- 個人用のレシピ管理 Web アプリケーションを開発し、自分のレシピを CRUD（作成・閲覧・編集・削除）操作で一元管理する

### 1-2. 目的

| 目的 | 説明 |
|---|---|
| **主目的** | 個人のレシピを Web 上で一元管理する |
| **副目的（学習）** | Ruby on Rails / Vue.js (Nuxt) / MySQL の習得、AWS 無料枠での本番デプロイ経験 |

### 1-3. 対象ユーザー

| 区分 | 内容 |
|---|---|
| 想定ユーザー数 | **1 名（開発者本人のみ）** |
| 利用シーン | 自宅 PC での閲覧・編集を想定 |
| ITリテラシー | 開発者本人のみのため考慮不要 |
| アカウント機能 | **不要**（シングルユーザー前提） |

### 1-4. 利用環境

#### ローカル開発環境（基本）

| 項目 | 内容 |
|---|---|
| OS | macOS（開発機）/ クライアントブラウザ問わず |
| バックエンド | Ruby on Rails 8.1.3（API モード）|
| フロントエンド | Nuxt 3（Vue.js 3 ベース）+ Tailwind CSS |
| データベース | MySQL 8.x（Docker コンテナ） |
| ポート | Rails 3000 / Nuxt 3001 / MySQL 3306 |

#### AWS デプロイ環境（Phase 4・任意）

| 項目 | 内容 |
|---|---|
| EC2 | t2.micro / t3.micro（無料枠） |
| RDS | db.t3.micro MySQL（無料枠）※ 2026-06-14 に廃止（Issue #133・RDS 無料枠スロット解放のため。最終スナップショット `recipe-board-db-final-20260614` 保全済み） |
| Web サーバー | Nginx（リバースプロキシ） |
| IaC | Terraform |

## 2. 前提条件と制約

### 2-1. 前提条件

- 開発者は IT 学習中の初学者であり、習熟度を考慮した段階的開発を行う
- スクール講師への提出を前提とし、現場のワークフロー（Issue → ブランチ → PR → マージ）を踏襲する
- AI 開発支援（Claude Code）の利用がスクールで推奨されている

### 2-2. 制約事項

| 区分 | 制約 |
|---|---|
| **技術スタック** | 前プロジェクト（task-board）で使用済の Java / PostgreSQL / React は**使用禁止**（講師指示） |
| **学習方針** | 「やったことがない技術を採用」（講師指示） |
| **コスト** | AWS は無料枠の範囲内で運用 |
| **期間** | スクール講座と並行して進めるため、過度な作り込みを避け早期完成を優先 |

## 3. 機能要件

### 3-1. MVP（必須・初期リリースに含む）

> **設計方針**: MVP は最小機能セットだが、**Phase 2 / 3 で機能を追加しやすい拡張性を考慮**して設計する。
> 具体的には、レシピと材料/手順は別テーブルで管理し（1:N 関連）、後からタグ・カテゴリ・画像等の関連エンティティを追加しやすい構造にする。
> 詳細は DB 設計書（別途作成予定）で定義。

#### 3-1-1. レシピ管理（CRUD）

| 機能 | 説明 |
|---|---|
| レシピ一覧表示 | 登録済みレシピをリスト形式で表示 |
| レシピ新規登録 | タイトル・材料・手順を入力してレシピを保存 |
| レシピ詳細表示 | 1 件のレシピの全情報を閲覧 |
| レシピ編集 | 既存レシピの内容を変更・保存 |
| レシピ削除 | 不要なレシピを削除 |

#### 3-1-2. レシピの構成要素

| 要素 | 必須/任意 | 説明 |
|---|---|---|
| タイトル | 必須 | レシピ名（例: 鶏の唐揚げ） |
| 材料リスト | 任意 | 0〜複数個。各材料は「名前」と「分量」を持つ |
| 手順リスト | 任意 | 0〜複数個。各手順は「順番」と「テキスト」を持つ |
| 作成日時 | 自動 | レシピ作成時に自動記録 |
| 更新日時 | 自動 | レシピ更新時に自動記録 |

### 3-2. Phase 2（MVP 完成後・余裕があれば）

| 機能 | 説明 |
|---|---|
| タグ機能 | レシピに自由なタグを付けて分類（例: 和食、簡単、夕食） |
| 検索機能 | タイトル・材料・タグを対象としたキーワード検索 |
| ソート | 作成日順 / 更新日順 / タイトル順 |

### 3-3. Phase 3（提出後の発展）

| 機能 | 説明 |
|---|---|
| 画像アップロード | 料理の写真を添付（S3 等のストレージ要件あり） |
| お気に入り機能 | よく作るレシピをマーク |
| カテゴリ別表示 | 主菜 / 副菜 / 汁物 等での絞り込み |
| **モバイル Safari 対応** | iPhone / iPad の Safari ブラウザで操作可能にする。レスポンシブデザインの調整 + iOS Safari 固有の挙動検証（task-board での useReminder クラッシュ事故等の対策含む） |

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| **対応ブラウザ（PC）** | Chrome / Safari（最新版）|
| **対応ブラウザ（モバイル）** | MVP では非対応。**モバイル Safari は Phase 3 以降で対応予定**（task-board での iOS Safari クラッシュ事故の教訓を踏まえ、別フェーズで個別検証する） |
| **想定ユーザー数** | 1 名（開発者本人） |
| **想定レシピ数** | 〜500 件程度（個人利用前提） |
| **応答時間** | 一覧表示 1 秒以内、詳細表示 1 秒以内（無料枠での合理的範囲） |
| **データ保持期間** | 削除しない限り永続保存 |
| **セキュリティ** | 機密情報は環境変数管理、`.env` は Git 管理外、pre-commit hook で機密情報スキャン |
| **可用性** | 個人利用のため SLA 規定なし |
| **バックアップ** | RDS の自動バックアップ（無料枠範囲）に依存。※ RDS 廃止（2026-06-14・Issue #133）後は最終スナップショット `recipe-board-db-final-20260614` のみ保持 |

## 5. 対象外（スコープ外）

以下は**本プロジェクトの範囲外**として明示する：

- ユーザー認証・サインアップ・ログイン機能（シングルユーザー前提）
- 他ユーザーとのレシピ共有・公開
- スマートフォンアプリ（PWA / iOS / Android ネイティブ）
- 食材在庫管理・買い物リスト連携
- 栄養計算
- 多言語対応（日本語のみ）
- レシピのインポート/エクスポート（CSV / JSON 等）
- 印刷最適化

> 上記は将来的に追加する可能性はあるが、本リリースでは実装しない。

## 8. 受入条件（検収基準）

### 8-1. 機能面

- [ ] レシピの新規登録ができる（タイトル必須、材料・手順は任意）
- [ ] レシピの一覧が表示される
- [ ] レシピの詳細が表示される
- [ ] レシピの編集ができる
- [ ] レシピの削除ができる
- [ ] 削除したレシピが一覧から消えている

### 8-2. 品質面

- [ ] フロント・バックエンドがエラーなく起動する
- [ ] ブラウザのコンソールにエラーが出ていない
- [ ] サーバーログにエラーが出ていない
- [ ] 主要ブラウザ（Chrome / Safari / Firefox）で動作確認済み

### 8-3. ドキュメント面

- [ ] README.md が最新の状態に保たれている
- [ ] 要件定義書 / 画面設計書 / DB 設計書 が docs/ 配下に揃っている
- [ ] CLAUDE.md / OPERATIONS.md が運用方針を反映している
- [ ] learning-notes.md に開発中の学びが記録されている

### 8-4. ワークフロー面

- [ ] すべての変更が Issue → ブランチ → PR → マージのフローで反映されている
- [ ] 直接 main への push が無い（履歴で確認可能）
- [ ] PR タイトル・コミットメッセージが Conventional Commits 形式・日本語

---

## 9. 変更管理

要件の追加・変更が生じた場合：

1. GitHub に Issue を起票（要件変更の背景・影響を明記）
2. ブランチを作成して本ファイルを編集
3. PR で変更理由とともにレビュー
4. マージ後、改訂履歴を更新

> 要件定義書の小さな更新も**ワークフローを省略しない**（提出物としての一貫性のため）。

## 10. 用語集

| 用語 | 説明 |
|---|---|
| レシピ | 1 つの料理の作り方を表すデータ単位（タイトル + 材料 + 手順） |
| 材料 | レシピに使う食材。名前と分量を持つ |
| 手順 | レシピの調理ステップ。順番とテキストを持つ |
| MVP | Minimum Viable Product。実用最小限の機能セット |
| CRUD | Create / Read / Update / Delete の略。基本的なデータ操作 |
| Phase | 開発段階の区切り（Phase 0〜4） |
